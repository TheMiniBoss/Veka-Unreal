# Spike 4.0 — Backdrop capture: engine post buffers (A) vs render graph element (B)

Date: 2026-11-22 · UE 5.8.4 · Windows, D3D12 · branch `cpp/phase-4.0-backdrop`

Question (`VEKAUI_PHASE0.md` §12.1): how does a Veka element read, blur and composite what is drawn behind it
(3D scene + UI drawn before it), for `backdropBlur`, frosted glass and Liquid Glass?

## What was built

Both methods behind one modifier, `FVekaBackdropModifier` (`backdropBlur`, `Modifiers/VekaEffectModifiers.h`), with
`Method = RenderGraph | EnginePostBuffer`, and a console command `Veka.BackdropSpike [radius] [full]` that shows them
side by side over the game viewport (PIE or `-game`).

- **A — engine Slate post buffers.** 5.8 has five window-wide post buffers (`ESlatePostRT_0..4`, render targets
  `/Engine/EngineResources/SlatePost{N}_RT`, settings `USlateRHIRendererSettings`, only buffer 0 enabled by default).
  An `SPostBufferUpdate` painted inside our widget copies the back buffer into buffer 0 and runs its processor
  (Gaussian blur through `UPostBufferBlurUpdater`); the panel then draws the render target with a brush whose UV region
  is the panel's window rect.
- **B — our render graph element** (`VekaUIRender/Public/VekaBackdrop.h`, `Shaders/Private/VekaBackdrop.usf`). An
  `ICustomSlateElement` (`FSlateDrawElement::MakeCustom`) whose `Draw_RenderThread(FRDGBuilder&, Inputs)`:
  copies only the panel's rect (+ a margin) from Slate's output texture, builds a **dual Kawase** pyramid
  (`BlurLevels(radius)` levels, down then up to half resolution), and composites inside the **rounded rect SDF** with
  tint and saturation, in our own pixel shader. GPU stat: `Veka Backdrop` (`stat gpu`).

## Results

| | A — engine post buffer | B — render graph element |
|---|---|---|
| Editor (PIE viewport inside the editor window) | **no capture**: flat grey (`Docs/Sync/Screens/phase4-0-pie-a-vs-b.jpg`) | blur OK |
| Game (`-game`, 1920 × 1080) | copy OK but **not blurred** (the processor did not run in this setup) (`phase4-0-game-a-vs-b.jpg`) | blur OK |
| Shape | rounded box brush only; refraction / aberration would need a UI material per effect | our shader: SDF of the shape, ready for refraction, specular rim, aberration (4b) |
| Limits | 5 buffers for the whole app, one processor per buffer (project settings), a full-frame copy per buffer used | none global: one copy of the panel's rect per element (4a: one per layer) |
| GPU, 380 × 240 panel, radius 24 | — | **0.09 ms** (`phase4-0-stat-gpu-panels.jpg`) |
| GPU, full screen 1920 × 1080, radius 24 | — | **0.20–0.22 ms** (`phase4-0-stat-gpu-fullscreen.jpg`) — §13 budget: glass < 1 ms |

Pitfalls found (and fixed for B):
- Slate keeps only a **weak pointer** to a custom drawer: an element made during paint must be kept alive until the
  render thread has drawn its frame. `MakeBackdropElement` keeps them and releases earlier frames' elements through
  a render command (render commands run in order, after those frames' Slate drawing).
- The elements matrix maps Slate absolute space onto the **whole output texture** (not `SceneViewRect`, which is the
  game viewport inside the editor window).
- 5.8 removed the legacy GPU profiler macros: `RDG_EVENT_SCOPE_STAT` replaces `RDG_GPU_STAT_SCOPE`.

## Decision

**B.** It works in the editor and in game, costs far less than the budget at full screen, has no global limit, and
its composite shader is exactly where Liquid Glass goes (refraction from the SDF normal, rim, aberration). A depends
on project-wide settings and materials, did not capture in editor windows and did not blur in our setup.

Next (4a): one capture + pyramid **per layer and frame** shared by every backdrop of the layer (instead of one per
element), quality levels, the fallback without backdrop, `backdropBlur` / `frostedGlass` in the language, inspector
and completion; the A path and the `SlateRHIRenderer` dependency are removed then.
